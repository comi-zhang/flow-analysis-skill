# PDF 对账单解析

银行 PDF 是整条链路里**最脏**的输入：列边界靠排版、字段会折行、每页重复表头。
下面的顺序是"先探、再解析、再验收"，不要跳步。

## 第 0 步：先探结构，别急着写解析器

```bash
python scripts/pdf_probe.py --pdf 交易流水.pdf --pages 8
```

探针回答三件事，直接决定后面怎么写：

| 探针输出 | 决定什么 |
| --- | --- |
| **金额行 / 日期行** 比值 | 高（≈100%）→ 可从行尾反向切金额、余额；低 → 必须用坐标定位列 |
| **折行卡号片段** 数 | >0 → 卡号/账号列不可信，余额链必须按「来源」分组 |
| **每页重复行** | 表头/页脚，解析时剔除 |

真实例子（某银行 103 页对账单，只探前 8 页）：

```
金额行 150（占日期行 100.0%）｜折行卡号片段 149｜孤立碎片 87
```

结论：金额能按行尾切（可信），但**每一条记录都发生了折行**，账户列会不可信。

## 第 1 步：剔除模板行——但阈值要严

每页重复的表头会变成"假交易行"，必须剔除。坑在阈值：

- 用"出现在 ≥50% 页面"判定模板 → **会误删真实数据**。
- 实测反例：`技有限公司 财付通扣款` 每页都出现，看着像模板，
  其实是**折行后字段残片**（对方行名被折断的尾巴）。
- 稳妥做法：模板 = 出现在 **≥90% 页面**的行；或干脆按**行号区间**剔除
  （每页固定前 N 行、后 M 行是页眉页脚）。

## 第 2 步：处理折行

### 不要用"8 位数字开头"判断日期

紧凑日期 `20250802` 是 8 位，**折行的卡号尾段（形如 `07639999`）也是 8 位**。
用正则 `^\d{8}` 判日期会把卡号当日期，字段从此全错位。

正确做法：8 位数字**还要满足真实日历**（`20250802` 月=08 合法；`07639999` 月=63 非法）。
`pdf_probe.py` 里已经这么做了。

### 一条记录会横跨多行

实测一条记录被拆成这样的多行（人名/商户/单号/卡号全部替换为虚构值）：

```
20250802 示例商户 C-0001 示例支付公司
技有限公司 快捷扣款
T-0000-0001
T-0000-0002
6
62363300726
C-0002 -7.80 2109.55
```

可见：金额和余额在**最后一行行尾**（`-7.80 2109.55`）。
所以解析顺序应是：

1. 用 `^日期` 定位每条记录的起点；
2. 取到**下一条记录起点**之间的所有行，拼成一条记录；
3. 从拼接结果的行尾反向切出「金额 余额」（两个数字最稳）；
4. 剩下的文本再按列模板或坐标切对手、摘要。

## 第 3 步：验收——余额链（唯一能证明"没解析错"的检查）

```bash
python scripts/qa_flow.py --input-dir masked/ --report qa.md
```

判定口径见 SKILL.md 步骤 3。要点：

- **与顺序无关**：问"本笔的前序余额是否存在"，不问"相邻两笔是否连续"。
- **按来源分组**，不按账户分组——折行会让卡号列不可信（见下）。
- **未匹配 = 1 是健康的**（账期首笔），判据是「链闭合」而不是「自洽率 100%」。

### 反例：账户列不可信会让"余额链"误报

实测某银行对账单有两个卡号，按卡号分组得到 18 处"断裂"，
**按来源合并后是 0 处**——而且它的"断裂"行的前序余额，都能在另一个卡号里找到。

原因：两个卡号属于**同一个余额主体**（同一账户的多张卡），
且卡号列来自折行的卡号单元格，本身就不可信。

**教训**：`qa_flow.py` 会同时给出「按来源」和「按账户」两个未匹配数，
来源级正常而账户级异常时，会标 `账户列可疑`——此时**不要用账户/卡号做维度分析**。

## 第 4 步：对手名不可信时的降级策略

PDF 换页处最容易丢列边界，把相邻单元格的残留粘到对手名上
（如 `司 C-XXXX 某某公司`，`司` 是上一行「…有限公司」的尾巴）。

实测某银行 PDF 出现把「朝朝宝转入（基金）」的对手名配成「拼多多」——
**金额、方向、余额都对，只有对手名列错位**。

所以：

- 金额/方向/余额 → 用余额链证明，可信；
- **对手名 → 不能做匹配主键**，只能做展示；
- 配对、分类等依赖对手名的逻辑，要标注"该来源对手名不可信"，或改用摘要列。

## 第 5 步：能不用 PDF 就别用

同一家银行通常也提供 CSV/Excel 导出。**CSV/Excel 结构性远好于 PDF**，
优先索取；PDF 只在拿不到结构化导出时使用。

## 安全

- PDF 含**真实姓名 + 完整卡号**，属于最高敏感级别：**绝不入库**（`.gitignore` 里加 `*.pdf`）。
- 解析产物在落盘前先过 `scripts/mask_pii.py`（读取即掩码）。
- `pdf_probe.py` 的输出也会带原文片段（姓名可能在内）：只在本机看，不要贴进报告或仓库。
- 原始 PDF 用完即删，或移到仓库外的私密目录。
